# Cleaning up finished work

Do this on your own, without being asked, as soon as the person reports that a task's pull request is merged (or you see it merged). The person gave standing permission to remove finished worktrees and their panes, but only ones that pass the proof in step 2; anything that does not pass is kept and raised with the person.

1. **Find what is done.** A task is done when its pull request is merged and its issue is closed (or, for an agent that only did read-only work, when it has reported and nothing more is planned for it). List the worktrees (`ls` the worktree root, `herdr worktree list`, `herdr workspace list`) and match each to its task.
2. **Prove each worktree is safe to remove before removing it.** Never trust the PR state alone, because a worker can add a commit after the PR was opened (a review fix) that never reached the base branch.
   - `git status -sb` must show no uncommitted changes.
   - The worktree's HEAD must be contained in the base branch on the remote: `gh api repos/<owner>/<repo>/compare/<base>...<head-sha>` returns `behind` with `ahead_by` 0. A 404 means the commit was never pushed, so it exists only in that local branch.
   - Do not rely on a local `origin/<base>` ref when fetch can fail; ask the host.
3. **Remove only the proven ones**, one at a time: `herdr worktree remove --workspace <id>` (no `--force`). It removes the worktree directory and its workspace with the panes and the agent in it. Report the path it returns.
4. **Keep what is not proven** and tell the person exactly why (for example "HEAD `<sha>` is not on the base branch"), then offer the choice: push it as a small follow-up pull request or drop it. Remove it after they decide.
5. **Leave alone:** worktrees whose task is in progress, worktrees of unrelated work, and branches unless the person asks for them. A worktree that was never started (clean, at the base) may be removed with the done ones, because recreating it costs one command.
6. Do the cleanup in the same pass as the card moves and the go message to the next worker, not as a separate round. After a merge, the order is: confirm the PR and the issue are closed, remove the proven worktree, move the cards, send the go message, tell the person what was removed and what was kept.
7. The standing permission covers worktrees and workspaces only. It never covers branches, an unproven worktree, a worktree whose task is still in progress, or anything the person did not create through this effort.
8. **Branches, when the person asks ("cleanup everything").** Limit it to the branches of this effort, never the older ones. Prove every tip first: compare each local and remote tip with the base on the host (`ahead_by` 0). Delete the local ones with `git branch -D` (merge-commit PRs leave the tips unmerged from the local HEAD's point of view, so `-d` refuses), the remote ones with `gh api -X DELETE repos/<owner>/<repo>/git/refs/heads/<branch>` (the host often deleted them already after the merge, so a failure may only mean "already gone"), then drop the stale remote-tracking refs with `git branch -dr origin/<branch>` when a fetch cannot prune them. The classifier may block the first attempt; if the person then says to run it, run exactly the proven list and nothing else. Offer a separate review of the older branches instead of deleting them.
9. Finish by listing what is left: worktrees, workspaces, agents of other efforts that are not yours, open follow-up issues, and anything kept and why.
