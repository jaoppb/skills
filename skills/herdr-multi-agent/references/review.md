# Review until approved

Every worker's branch diff is reviewed by fresh read-only specialist reviewers under the installed `diff-review` skill ([diff-review/SKILL.md](../../diff-review/SKILL.md)) before the coordinator merges anything. This is a smart delta loop, not a fixed number of rounds. Coordinators can also run an optional pre-wave `plan-review` ([plan-review/SKILL.md](../../plan-review/SKILL.md)) on the issue breakdown and wave plan before confirming waves ([waves.md](waves.md)).

## The diff-review loop (worker)

1. **Verify `lenses: [<baseline>, ...]` before dispatching**: When implementation is done and the project's check passes, check the branch diff (`git diff origin/<base>...HEAD`) against the content-aware baseline, built-in triggers, and discovered project/user specialist agents in the installed `diff-review` skill ([diff-review/SKILL.md](../../diff-review/SKILL.md), ignoring `herdr-multi-agent`-managed `herdr-*`, `diff-review-*`, `plan-review-*`, and legacy `review-*` wrappers in `~/.kiro/agents/`). The coordinator owns `lenses: [<baseline>, ...]` (`code-quality` for code diffs, `docs-quality` for docs-only diffs, or both for mixed diffs with substantial docs changes). If the diff triggers **any** lens (including a newly needed baseline) not in the task's assigned `lenses`, stop, send `[TREE <task>]` naming the newly triggered lens(es) and files, and wait for the coordinator to update `lenses` and re-check wave overlap before running or finishing review; never self-retag.
2. **Dispatch one fresh read-only reviewer per active lens**: Follow your host protocol ([protocols/claude.md](protocols/claude.md), [protocols/agy.md](protocols/agy.md), [protocols/kiro.md](protocols/kiro.md), or [protocols/fallback.md](protocols/fallback.md) temporary Herdr review tabs when native sub-agents are unavailable) to dispatch one fresh read-only reviewer per active lens in parallel using two-tier model mapping (`flagship` vs `fast/balanced`, [agent-effort.md](agent-effort.md)). The worker never reviews its own diff and never folds multiple lenses into one reviewer. UI tasks (`frontend` lens) delegate directly to `references/lenses/frontend.md` of the installed `diff-review` skill ([frontend.md](../../diff-review/references/lenses/frontend.md)): run Impeccable `audit` when installed/initialized, otherwise fall back to `frontend.md`'s built-in UI/WCAG checklist without sending `[BLOCKED]`.
   - **Canonical diff-reviewer brief & artifacts**: Pass every reviewer (a) its single lens guide path (`references/lenses/<lens>.md` of `diff-review`, or the discovered external specialist file), (b) the task/issue context and confirmed `grill-me` decisions, (c) the branch diff (`git diff origin/<base>...HEAD`) and changed-file list (`git diff --name-only origin/<base>...HEAD`), (d) on Round N+1, the round delta (`git diff <prev_round_sha>..HEAD`) and that lens's prior `fixed` / `rejected` / `deferred` ledger, and (e) the strict read-only contract (**report findings only mapped to `blocker`, `material`, `nitpick`, or `out-of-scope`; edit nothing and run no mutating commands**). Whenever git is sandboxed in a worktree or reviewers run in temporary CLI tabs, write `/tmp/diff-<task>-r<n>.patch`, `/tmp/files-<task>-r<n>.txt`, and (on Round N+1) `/tmp/delta-<task>-r<n>.patch` before dispatching.
3. **Fix & run smart delta re-runs**: Record `prev_round_sha = HEAD` and per-lens `fixed` / `rejected` / `deferred` findings in a temporary ledger under `/tmp` (or session scratch; never commit it). After fixing real findings in a new commit (preserving the parent reference) and re-running the project check, Round N+1 re-runs **only** the active baseline lens(es) (`code-quality` and/or `docs-quality`), any lens that rejected in Round N, and any lens whose domain files changed in `git diff <prev_round_sha>..HEAD` ([diff-review/SKILL.md](../../diff-review/SKILL.md)). If a fix commit newly triggers an unassigned lens, send `[TREE <task>]` and wait for coordinator retag before completing review.
4. **Approval bar**: A round **approves** only when every active lens returns **zero `blocker` (P0) and zero `material` (P1) findings**. What may remain: `nitpick` (P2/P3) items rejected with a written reason, and out-of-scope items deferred with a written reason.
5. **Escalation & conflicts**: No fixed round count. After five rounds without approval, when a finding needs a decision outside the worker's scope, or when two lenses demand contradictory changes, stop and send `[QUESTION <task>]` with both positions/options and a recommendation instead of picking silently or looping on.
6. **Post-approval commits**: Any commit made after approval (rebase conflict resolution, CI fix, PR review comment) requires another delta round before the approval holds.

## The report and pull request

Once approved and project checks pass, the worker automatically pushes the branch (`git push -u origin <branch>`) and creates the pull request using `gh pr create`.

`[DONE <task>]` carries the PR URL, branch, approved HEAD commit, check result, and a Review paragraph ("Review: approved in round N") reporting per-lens round counts and fixed, rejected (with reason), and deferred (with reason) summaries. A `[DONE]` without an approved review or PR link is not ready.

## The coordinator

- Check the PR and claim: verify with `gh pr view`, confirm the approved HEAD matches the PR commit, and verify all assigned `lenses` are accounted for in the `[DONE]` summary.
- Monitor CI checks until green, then present the pull request to the person for merge authorization. Merging remains strictly the person's decision. If CI fails, the worker fixes it and, if code/docs changed, runs another delta review round.
- Put this rule and the task's `lenses: [<baseline>, ...]` in every worker's first prompt (see [worker-prompts.md](worker-prompts.md)), in the task brief even when the brief is a file.

## Optional pre-wave `plan-review` (coordinator)

When the person requests a pre-wave review or the issue breakdown / draft wave plan looks under-refined, oversized, or high-risk ([waves.md](waves.md)):

1. **Snapshot to `/tmp` first**: Fetch all task/issue bodies, parent epic/spec context, confirmed `grill-me` decisions, and the draft wave plan into `/tmp/plan-<slug>-r<n>.md` (and on Round N+1 compute `diff -u /tmp/plan-<slug>-r<n-1>.md /tmp/plan-<slug>-r<n>.md > /tmp/plan-delta-<slug>-r<n>.diff`). Reviewers never need shell, write, network, or MCP tools — only `/tmp` and repository read access.
2. **Dispatch one fresh read-only sub-agent per active `plan-review` lens**: Follow your host protocol ([protocols/claude.md](protocols/claude.md), [protocols/agy.md](protocols/agy.md), [protocols/kiro.md](protocols/kiro.md), or [protocols/fallback.md](protocols/fallback.md)) using two-tier model mapping (`flagship`: `plan-quality`, `feasibility`, `slicing-and-dependencies`, `risk`; `fast/balanced`: `product-alignment` and default external specialists). Pass each reviewer its lens guide path (`references/lenses/<lens>.md` of `plan-review`), `/tmp/plan-<slug>-r<n>.md` (plus `/tmp/plan-delta-<slug>-r<n>.diff` and prior settled findings on Round N+1), and the strict read-only contract.
3. **Present or iterate**: Surface `blocker` / `material` findings (and any cross-lens conflicts) to the person before confirming the wave plan; after any plan/issue revision, run a Round N+1 delta review per [plan-review/SKILL.md](../../plan-review/SKILL.md) until approved or explicitly waived by the person.
